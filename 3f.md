# Subarray Algorithms
This section covers a few common subarray algorithms that don't fit neatly into the previous sections, most notably Kadane's Algorithm and Prefix Sums.

## Kadane's Algorithm
Kadane's Algorithm finds the **maximum sum of a contiguous subarray** in `O(n)` time, and works even when the array contains negative numbers.

### When to use
1. You're asked for the maximum (or minimum) sum of a contiguous subarray.
2. The array may contain negative numbers, so a sliding window won't work.

### Algorithm
The key idea: at each index, decide whether to extend the previous subarray or start a new one from the current element.

Given a non-empty list of integers, return the maximum sum of any contiguous subarray:
```{code-block} python
---
linenos:
---
def max_subarray(nums):
    current = best = nums[0]

    for num in nums[1:]:
        current = max(num, current + num)
        best = max(best, current)

    return best
```
- `current` is the maximum subarray sum ending at the current element.
- `max(num, current + num)` chooses between starting a new subarray and extending the previous one.
- `best` is the maximum sum found anywhere so far.

For `[-2, 1, -3, 4, -1, 2, 1, -5, 4]`, the best subarray is `[4, -1, 2, 1]`, so the function returns `6`.

### Tips and tricks
- Initialize with the first element (not `0`) so all-negative arrays return the largest single element.
- Kadane's algorithm is dynamic programming with constant space: only the previous state is needed.
- To find the minimum-sum subarray, replace both `max` operations with `min`.

## Maximum Product Subarray

The maximum-product problem resembles Kadane's algorithm, but multiplication by a negative number swaps the roles of large and small values. A very negative running product can become the new maximum when multiplied by another negative number. Therefore, track both the maximum and minimum product ending at the current element.

### When to use
1. You're asked for the maximum product of a contiguous subarray.
2. The input may contain positive numbers, negative numbers, and zeros.

### Algorithm

```{code-block} python
---
linenos:
---
def max_product_subarray(nums):
    result = max(nums)
    min_so_far, max_so_far = 1, 1

    for num in nums:
        tmp = num * max_so_far
        max_so_far = max(num * max_so_far, num * min_so_far, num)
        min_so_far = min(tmp, num * min_so_far, num)
        result = max(result, max_so_far)

    return result
```

- At each element, consider three choices: extend the previous maximum product, extend the previous minimum product, or start a new subarray at `num`.
- `tmp` saves the product using the previous `max_so_far` before `max_so_far` is overwritten. The minimum calculation needs both previous states.
- Starting again at `num` handles zeros naturally: after a zero, a later nonzero value can begin a new subarray.
- `min_so_far` must be retained because multiplying it by a negative number may produce the next `max_so_far`.

For `[2, 3, -2, 4]`, the function returns `6` from `[2, 3]`. For `[-2, 3, -4]`, it returns `24` because the two negative values make the product positive.

This algorithm takes `O(n)` time and `O(1)` auxiliary space.

## Prefix Sum
A prefix sum array stores the running total of elements, letting you compute the sum of any subarray in `O(1)` after an `O(n)` preprocessing step.

### When to use
1. You have many range-sum queries over an array that doesn't change.
2. You need to count or find subarrays whose sum equals a target (often paired with a hashmap).

### Algorithm
The key idea: the sum of a subarray `nums[i:j]` equals `prefix[j] - prefix[i]`. So a subarray sums to `k` whenever `prefix[j] - prefix[i] == k`, i.e. `prefix[i] == prefix[j] - k`. As we build the running sum, we count how many earlier prefix sums equal `cur - k`.

Given a list of integers, count the number of contiguous subarrays that sum to `k`:
```{code-block} python
---
linenos:
---
def subarray_sum(nums, k):
    count = 0
    cur = 0
    seen = {0: 1}   # a prefix sum of 0 has occurred once (empty prefix)
    for x in nums:
        cur += x
        count += seen.get(cur - k, 0)
        seen[cur] = seen.get(cur, 0) + 1
    return count
```
- `cur` is the running prefix sum up to the current element.
- `seen` maps each prefix sum to how many times it has occurred so far.
- For each element we add the number of earlier prefixes equal to `cur - k`, since each one marks a subarray ending here that sums to `k`.

### Tips and tricks
- To count subarrays summing to `k`, store prefix sums seen so far in a hashmap and look for `prefix - k` as you iterate (a one-pass solution).
- Prefix sums work with negative numbers, which is exactly where sliding window fails.
- The idea generalizes to 2D (prefix sums over a matrix) for submatrix sum queries.
