# Subarray Algorithms
This section covers a few common subarray algorithms that don't fit neatly into the previous sections, most notably Kadane's Algorithm and Prefix Sums.

## Kadane's Algorithm
Kadane's Algorithm finds the **maximum sum of a contiguous subarray** in `O(n)` time, and works even when the array contains negative numbers.

### When to use
1. You're asked for the maximum (or minimum) sum of a contiguous subarray.
2. The array may contain negative numbers, so a sliding window won't work.

### Algorithm
The key idea: at each index, decide whether to extend the previous subarray or start a new one from the current element. Here we also track the start and end indices of the best subarray.

Given a list of stock profits (integers), return the left index, right index, and max profit of any contiguous subarray:
```{code-block} python
---
linenos:
---
def max_profit(profits):
    cur = best = profits[0]
    start = 0
    left = right = 0
    for i in range(1, len(profits)):
        if profits[i] > cur + profits[i]:
            cur = profits[i]
            start = i
        else:
            cur += profits[i]
        if cur > best:
            best = cur
            left, right = start, i
    return left, right, best
```
- `cur` is the best subarray sum ending at the current index.
- When starting fresh at `profits[i]`, we reset `start` to the current index.
- Whenever `cur` beats `best`, we record the window `[start, i]` as the new best.

### Tips and tricks
- Initialize with the first element (not `0`) so all-negative arrays return the largest single element.
- The same pattern extends to maximum product subarray by tracking both a running max and min (since a negative can flip them).

## Prefix Sum
A prefix sum array stores the running total of elements, letting you compute the sum of any subarray in `O(1)` after an `O(n)` preprocessing step.

### When to use
1. You have many range-sum queries over an array that doesn't change.
2. You need to count or find subarrays whose sum equals a target (often paired with a hashmap).

### Algorithm
The key idea: the sum of a subarray `nums[i:j]` equals `prefix[j] - prefix[i]`. So a subarray sums to `k` whenever `prefix[j] - prefix[i] == k`, i.e. `prefix[i] == prefix[j] - k`. As we build the running sum, we count how many earlier prefix sums equal `cur - k`.

Given a list of integers, count the number of contiguous subarrays that sum to `k`:
```{code-block} python
---
linenos:
---
def subarray_sum(nums, k):
    count = 0
    cur = 0
    seen = {0: 1}   # a prefix sum of 0 has occurred once (empty prefix)
    for x in nums:
        cur += x
        count += seen.get(cur - k, 0)
        seen[cur] = seen.get(cur, 0) + 1
    return count
```
- `cur` is the running prefix sum up to the current element.
- `seen` maps each prefix sum to how many times it has occurred so far.
- For each element we add the number of earlier prefixes equal to `cur - k`, since each one marks a subarray ending here that sums to `k`.

### Tips and tricks
- To count subarrays summing to `k`, store prefix sums seen so far in a hashmap and look for `prefix - k` as you iterate (a one-pass solution).
- Prefix sums work with negative numbers, which is exactly where sliding window fails.
- The idea generalizes to 2D (prefix sums over a matrix) for submatrix sum queries.
