# Tree Traversal Strategies
This section covers different tree traversal strategies for solving tree problems.

## Breadth First Search

Breadth-first search visits a tree level by level using a queue. In an undirected adjacency list, each edge appears in both directions. Store the parent with each queued node so the traversal does not immediately follow the same edge backward.

```{code-block} python
---
linenos:
---
from collections import deque


def bfs(tree, root, parent=None):
    order = []
    queue = deque([(root, parent)])

    while queue:
        node, parent = queue.popleft()
        order.append(node)

        for neighbor in tree[node]:
            if neighbor == parent:
                continue
            queue.append((neighbor, node))

    return order
```

- **Time:** `O(V)` because a tree has `V - 1` edges.
- **Auxiliary space:** `O(V)` in the worst case for the queue, excluding the returned traversal.

## Depth First Search

Depth-first search follows one branch as deeply as possible before exploring the next branch. Pass the current node as the parent of each recursive call, and skip that parent when examining neighbors.

```{code-block} python
---
linenos:
---
def dfs(tree, root, parent=None):
    order = []

    def visit(node, parent):
        order.append(node)

        for neighbor in tree[node]:
            if neighbor == parent:
                continue
            visit(neighbor, node)

    visit(root, parent)
    return order
```

- **Time:** `O(V)` because every node and edge is processed a constant number of times.
- **Auxiliary space:** `O(H)` for the recursion stack, where `H` is the tree height, excluding the returned traversal.

The parent check is sufficient because a valid tree has no cycles other than seeing each undirected edge from both endpoints. In a general graph, a longer cycle can return through a node other than the parent, so use a `visited` set instead.

Binary trees represented only with `left` and `right` child pointers do not point back to their parents, so the preorder, inorder, and postorder examples below do not need a parent check.

## Preorder Traversal
Preorder visits the node **before** its children, in the order: root, root.left, root.right.

Recursive:
```
def preorder(root):
    return [root.val] + preorder(root.left) + preorder(root.right) if root else []
```

Iterative (use a stack, push right before left so left is processed first):
```
def preorder(root):
    res, stack = [], [root]
    while stack:
        node = stack.pop()
        if node:
            res.append(node.val)
            stack.append(node.right)
            stack.append(node.left)
    return res
```

When to use it:
- Copying or serializing a tree (the root is emitted first, so it can be rebuilt top-down).
- Any problem where a node must be processed before its subtrees.
- You are passing information down to the subtrees, so typically involves multiple arguments

Tips and tricks:
- Preorder processes the root first, then recurses left, then right.
- Combined with an inorder traversal, a preorder traversal uniquely reconstructs a binary tree.

## Inorder Traversal
Inorder visits the node **between** its children, in the order: root.left, root, root.right.

Recursive:
```
def inorder(root):
    return inorder(root.left) + [root.val] + inorder(root.right) if root else []
```

Iterative (walk left as far as possible, then process and turn right):
```
def inorder(root):
    res, stack = [], []
    node = root
    while node or stack:
        while node:
            stack.append(node)
            node = node.left
        node = stack.pop()
        res.append(node.val)
        node = node.right
    return res
```

When to use it:
- Reading a Binary Search Tree (BST) in sorted order.
- Finding the kth smallest/largest element in a BST.

Tips and tricks:
- An inorder traversal of a valid BST is sorted.
- Inorder traversal defines left subtree, root, and right subtree.

## Postorder Traversal
Postorder visits the node **after** its children, in the order: root.left, root.right, root.

Recursive:
```
def postorder(root):
    return postorder(root.left) + postorder(root.right) + [root.val] if root else []
```

Iterative (build root, right, left like a reversed preorder, then reverse the result):
```
def postorder(root):
    res, stack = [], [root]
    while stack:
        node = stack.pop()
        if node:
            res.append(node.val)
            stack.append(node.left)
            stack.append(node.right)
    return res[::-1]
```

When to use it:
- Deleting or freeing a tree (children are handled before the parent).
- Bottom-up problems where a node's result depends on its subtrees, such as computing height or diameter.

Tips and tricks:
- Postorder processes the root last, after both subtrees are done.
- Useful whenever a parent's value is aggregated from its children.

## Advanced: Tree DP

Tree dynamic programming (tree DP) stores information for each node so that results from smaller subtrees can be combined into results for larger subtrees. Most tree DP solutions use DFS because the recursive call stack naturally represents the parent-child relationship.

A common state is `dp[node] = the answer for the subtree rooted at node`. The tree can be rooted at any node (often node `0`), even when the input is an undirected tree.

General tips and tricks:

- **Define the state precisely.** State whether `dp[node]` describes only the node's subtree or the entire tree when rooted at that node.
- **Use postorder for bottom-up information.** Visit every child before computing the current node. Examples include subtree size, height, and tree diameter.
- **Use preorder for top-down information.** Compute a child's state from its parent's completed state. This is useful when information from outside the child's subtree matters.
- **Pass the parent.** Skip `neighbor == parent` so an undirected edge is not followed backward.
- **Return everything the parent needs.** One DFS can return multiple values, such as `(subtree_size, best_path)`.
- **Choose clear base cases.** Leaves often contribute a count of `1`, a height of `0`, or another identity value for the transition.
- **Check what is being counted.** A path with `k` nodes has `k - 1` edges; many off-by-one errors come from mixing the two definitions.
- **Look for a second pass.** If the answer is needed for every possible root, first solve for one root and then use rerooting DP to move that result to its neighbors.
- **Watch Python's recursion depth.** A tree can be a long chain, so use an iterative traversal or raise the recursion limit when the constraints are large.

A basic bottom-up template is:

```{code-block} python
---
linenos:
---
def tree_dp(tree, root=0):
    if not tree:
        return []

    dp = [0] * len(tree)

    def dfs(node, parent):
        # Identity value for a subtree containing only this node.
        dp[node] = 1

        for neighbor in tree[node]:
            if neighbor == parent:
                continue

            dfs(neighbor, node)
            dp[node] += dp[neighbor]  # Combine the child's result.

    dfs(root, -1)
    return dp
```

In this example, `dp[node]` is the size of the subtree rooted at `node`. Replace the state and combine operation to fit the problem.

### Rerooting DP

Rerooting DP finds an answer for every node as though each node were the root. A typical solution uses two traversals:

1. A postorder DFS calculates subtree information and the answer for one chosen root.
2. A preorder DFS moves, or *reroots*, that answer from each parent to its children.

For example, suppose `answer[node]` should contain the sum of the distances from `node` to all other nodes. Root the tree at node `0` and first compute:

- `subtree_size[node]`: the number of nodes in `node`'s subtree.
- `answer[0]`: the sum of every node's depth from node `0`.

When the root moves across an edge from `node` to its child `neighbor`:

- The `subtree_size[neighbor]` nodes in the child's subtree become one edge closer.
- The other `n - subtree_size[neighbor]` nodes become one edge farther away.

Therefore:

```text
answer[neighbor]
= answer[node] - subtree_size[neighbor] + (n - subtree_size[neighbor])
= answer[node] + n - 2 * subtree_size[neighbor]
```

```{code-block} python
---
linenos:
---
def sum_of_distances(n, edges):
    """Return the sum of distances from each node to every other node."""
    if n == 0:
        return []

    tree = [[] for _ in range(n)]
    for u, v in edges:
        tree[u].append(v)
        tree[v].append(u)

    subtree_size = [1] * n
    answer = [0] * n

    # First pass: compute subtree sizes and the distance sum for root 0.
    def postorder(node, parent, depth):
        answer[0] += depth

        for neighbor in tree[node]:
            if neighbor == parent:
                continue

            postorder(neighbor, node, depth + 1)
            subtree_size[node] += subtree_size[neighbor]

    # Second pass: derive each child's answer from its parent's answer.
    def preorder(node, parent):
        for neighbor in tree[node]:
            if neighbor == parent:
                continue

            answer[neighbor] = (
                answer[node] + n - 2 * subtree_size[neighbor]
            )
            preorder(neighbor, node)

    postorder(0, -1, 0)
    preorder(0, -1)
    return answer
```

For `n = 6` and `edges = [[0, 1], [0, 2], [2, 3], [2, 4], [2, 5]]`, the result is `[8, 12, 6, 10, 10, 10]`.

- **Time:** `O(n)` because each traversal visits every node and edge once.
- **Auxiliary space:** `O(n)` for the adjacency list, arrays, and recursion stack.
- **Key requirement:** The input must be a tree. The parent check alone is not sufficient for a general graph with cycles.
