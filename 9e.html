3D DP and Beyond#

Some problems need three or more variables to describe a state, giving a table like dp[i][j][k]. The idea is identical to lower dimensions — define the state, write the recurrence, handle base cases — but memory becomes the main concern, since the table grows as the product of every dimension’s size.

When to use#

  1. A single index pair isn’t enough to capture the state — you’re tracking an extra quantity such as a count, a budget, a number of transactions, or a second capacity.

  2. Examples: 0/1 knapsack with two constraints, buy/sell stock with at most k transactions, or paths through a grid with a remaining “fuel” budget.

Algorithm#

A common 3D problem is Ones and Zeroes: given binary strings and budgets of m zeros and n ones, find the largest subset you can form. This is a 0/1 knapsack with two capacities, so the full state is dp[i][z][o] — using the first i strings, with z zeros and o ones available.

 1def find_max_form(strs, m, n):
 2    counts = [(s.count("0"), s.count("1")) for s in strs]
 3    L = len(strs)
 4    # dp[i][z][o] = max subset size using first i strings with z zeros, o ones
 5    dp = [[[0] * (n + 1) for _ in range(m + 1)] for _ in range(L + 1)]
 6    for i in range(1, L + 1):
 7        zeros, ones = counts[i - 1]
 8        for z in range(m + 1):
 9            for o in range(n + 1):
10                dp[i][z][o] = dp[i - 1][z][o]              # skip string i
11                if z >= zeros and o >= ones:               # take string i
12                    dp[i][z][o] = max(dp[i][z][o],
13                                      dp[i - 1][z - zeros][o - ones] + 1)
14    return dp[L][m][n]

  • dp[i][z][o] is the best subset size using the first i strings within both budgets.

  • As in 0/1 knapsack, each string is either skipped or taken; taking it consumes its zeros and ones.

  • The answer is dp[L][m][n] — all strings considered, full budgets available.

Memory savings with bottom-up#

The full table above uses O(L * m * n) memory. But notice dp[i][...] only ever reads from dp[i - 1][...] — the previous “layer.” This is where bottom-up shines: we can drop the first dimension entirely and reuse a single 2D array, updating it in place.

The trick is the same as the 1D knapsack loop direction: iterate the capacity dimensions downward so each string is used at most once.

1def find_max_form(strs, m, n):
2    dp = [[0] * (n + 1) for _ in range(m + 1)]        # drop the i dimension
3    for s in strs:
4        zeros, ones = s.count("0"), s.count("1")
5        for z in range(m, zeros - 1, -1):             # downward = use each string once
6            for o in range(n, ones - 1, -1):
7                dp[z][o] = max(dp[z][o], dp[z - zeros][o - ones] + 1)
8    return dp[m][n]

  • We collapsed a 3D table into a 2D one, cutting memory from O(L * m * n) to O(m * n).

  • Iterating z and o downward ensures dp[z - zeros][o - ones] still refers to the previous layer (before this string), preserving the 0/1 semantics.

Tips and tricks#

  • The dimension you iterate over is usually the one you can drop. If dp[i] only depends on dp[i - 1], keep just one or two layers instead of the whole thing (a “rolling array”). A 3D table often collapses to 2D, and a 2D table to 1D.

  • The savings grow with dimensions: dropping one axis of a d-dimensional table divides memory by that axis’s size — far more impactful than in low-dimensional DP.

  • Top-down memoization can’t drop dimensions this way (it may revisit any state at any time), so bottom-up is the tool for tight memory. Reach for it when the full table would be too large to fit.

  • Order matters when reusing an array in place: loop downward to reuse the previous layer (0/1, each item once), upward to allow the current layer (unbounded reuse) — the same rule as Knapsack DP.
