# Stacks
This section will go over problems that are easily solvable using the stack data structure. 

## When to use
1. Nested elements in an array: operations in a calculator, parentheses
2. When a problem involves monotonically increasing or decreasing elements

## Data Structure
Stacks typically either store single elements or tuples (e.g. (a, b)). 
- Tuples can conveniently keep track of any combination of local minima, maxima, index, and value

Some advantages of stacks include:
- Most problems will typically compare some value with the top-most element of the stack (e.g. stack[-1])
- Monotonic stack: can keep track of the local maxima or local minima element in some array by appending only when greater or less than top-most element of stack. 
- Stacks are also very useful for elements of the "destructive" or "combining" nature, e.g. (5 + 3) becomes 8, two meteors hit each other and break, etc.

## Monotonic Stack
A monotonic stack is a stack whose elements are always kept in sorted order (either entirely increasing or entirely decreasing from bottom to top). Before pushing a new element, you first pop every element that would break that order. This lets you find, for each element, the **nearest greater or smaller** element in `O(n)` time overall.

### When to use
1. For each element, you need the next (or previous) greater/smaller element.
2. You're asked about spans, ranges, or "how far until a bigger/smaller value" — e.g. daily temperatures, stock spans, largest rectangle in a histogram.
3. A brute-force solution would compare every pair (`O(n^2)`) but the answer only depends on the nearest qualifying neighbor.

### Algorithm
The key rule: maintain the invariant by popping before you push. Whatever gets popped has just found its "answer" (the current element). This example finds, for each element, the number of days until a warmer temperature:
```{code-block} python
---
linenos:
---
def daily_temperatures(temps):
    res = [0] * len(temps)
    stack = []                          # holds indices, temps decreasing bottom->top
    for i, t in enumerate(temps):
        while stack and temps[stack[-1]] < t:
            j = stack.pop()             # temps[i] is the next warmer day for j
            res[j] = i - j
        stack.append(i)
    return res
```
- The stack stores **indices** whose temperatures are decreasing from bottom to top.
- When the current temperature is warmer than the top, that top element has found its answer, so we pop and record it.
- Each index is pushed and popped at most once, giving `O(n)` total time.

### Building the smallest result
A closely related class of problems asks you to remove elements to produce the **smallest (or lexicographically smallest) possible result**. The same monotonic stack applies, but now popping is a *greedy* choice: a larger element sitting to the left of a smaller one should be removed, because putting the smaller element earlier makes the result smaller.

This example removes `k` digits from a number to make it as small as possible:
```{code-block} python
---
linenos:
---
def remove_k_digits(num, k):
    stack = []                          # kept increasing bottom->top
    for d in num:
        while stack and k > 0 and stack[-1] > d:
            stack.pop()                 # a bigger digit earlier -> pop to shrink result
            k -= 1
        stack.append(d)
    stack = stack[:len(stack) - k]      # if removals remain, drop from the end
    return "".join(stack).lstrip("0") or "0"
```
- The stack stays increasing, so smaller digits bubble toward the front.
- Each pop uses one of the `k` allowed removals; we stop popping once `k` runs out.
- Any leftover removals are taken from the end (the largest trailing digits), and we strip leading zeros.

### Tips and tricks
- **Decreasing** stack → finds the next *greater* element; **increasing** stack → finds the next *smaller* element.
- For "smallest result" problems, keep an **increasing** stack and pop a larger element whenever a smaller one arrives (subject to a removal budget or a "must keep" constraint).
- Store **indices** rather than values when you need distances or spans (you can still look up the value with `arr[stack[-1]]`).
- Iterate left-to-right for "next" relationships, or right-to-left for "previous" relationships.
- Anything left on the stack at the end never found a qualifying neighbor (use a sentinel or default value for these).
