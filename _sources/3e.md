# Intervals

Interval problems usually represent a range as `[start, end]`. Three of the most useful approaches are:

| Approach | When to use it | Common examples |
|---|---|---|
| Sort by start time | Process intervals from left to right and combine or compare overlapping ranges | Merge Intervals, Insert Interval, Meeting Rooms |
| Sort by end time | Greedily keep the interval that finishes earliest | Non-overlapping Intervals, Activity Selection, Minimum Number of Arrows |
| Sweep line with `(event, delta)` | Track how many intervals are active as boundaries are crossed | Meeting Rooms II, Maximum Overlap, Car Pooling |

Always decide what happens when one interval ends exactly when another begins. For scheduling problems, intervals are commonly treated as half-open ranges `[start, end)`, so `[1, 3)` and `[3, 5)` do not overlap. Other problems may treat both endpoints as included.

## 1. Sort by Start Time

### When to Use It

Sort by start time when intervals should be processed from left to right. This is especially useful when:

- overlapping intervals must be merged;
- each interval only needs to be compared with the previous interval;
- a new interval must be inserted into an existing set of intervals;
- you only need to determine whether any overlap exists.

After sorting, an interval can only overlap the last interval already added to the result. This gives a useful invariant: the output contains all merged intervals seen so far, and its last interval is the only one that might overlap the current interval.

### Example: Merge Intervals

```{code-block} python
---
linenos:
---
def merge_intervals(intervals):
    if not intervals:
        return []

    intervals = sorted(intervals)
    merged = [intervals[0][:]]

    for start, end in intervals[1:]:
        previous_end = merged[-1][1]

        if start <= previous_end:
            merged[-1][1] = max(previous_end, end)
        else:
            merged.append([start, end])

    return merged


intervals = [[1, 3], [2, 6], [8, 10], [9, 12]]
print(merge_intervals(intervals))
# [[1, 6], [8, 12]]
```

The condition `start <= previous_end` treats touching endpoints as overlapping. Change it to `start < previous_end` when working with half-open intervals that should remain separate when one ends exactly as another begins.

- **Time:** `O(n log n)` for sorting, followed by an `O(n)` scan.
- **Space:** `O(n)` for the sorted copy and output.

## 2. Sort by End Time

### When to Use It

Sort by end time when the goal is to select as many non-overlapping intervals as possible. The greedy choice is to keep the interval that ends earliest because it leaves the most room for future intervals.

This approach is useful for:

- finding the maximum number of compatible intervals;
- finding the minimum number of intervals to remove;
- scheduling the most meetings or activities;
- choosing the minimum number of arrows needed to cover balloon intervals.

### Example: Maximum Number of Non-Overlapping Intervals

```{code-block} python
---
linenos:
---
def max_non_overlapping(intervals):
    intervals = sorted(intervals, key=lambda interval: interval[1])
    count = 0
    previous_end = float("-inf")

    for start, end in intervals:
        if start >= previous_end:
            count += 1
            previous_end = end

    return count


intervals = [[1, 2], [2, 3], [3, 4], [1, 3]]
print(max_non_overlapping(intervals))  # 3
```

For half-open intervals, `start >= previous_end` allows one interval to start when the previous one ends. If touching endpoints count as overlapping, use `start > previous_end` instead.

The minimum number of intervals to remove is:

```python
len(intervals) - max_non_overlapping(intervals)
```

- **Time:** `O(n log n)` for sorting, followed by an `O(n)` scan.
- **Space:** `O(n)` for the sorted copy.

## 3. Sweep-Line Algorithm

### When to Use It

Use a sweep line when the answer depends on how many intervals are active at each point. Convert every interval into two events:

- `(start, +1)` because an interval becomes active;
- `(end, -1)` because an interval stops being active.

Sort the events and process them from left to right while maintaining a running total. This is useful for:

- finding the maximum number of overlapping intervals;
- calculating the minimum number of meeting rooms;
- checking whether capacity is exceeded;
- applying additions or removals over ranges.

### Example: Minimum Number of Meeting Rooms

```{code-block} python
---
linenos:
---
def min_meeting_rooms(intervals):
    events = []

    for start, end in intervals:
        events.append((start, 1))
        events.append((end, -1))

    active = 0
    most_active = 0

    for _, delta in sorted(events):
        active += delta
        most_active = max(most_active, active)

    return most_active


meetings = [[0, 30], [5, 10], [15, 20]]
print(min_meeting_rooms(meetings))  # 2
```

Tuple sorting handles ties correctly for half-open intervals: `(time, -1)` is processed before `(time, +1)`, so a room is released before another meeting starts at the same time. If both endpoints are included and touching intervals overlap, start events must be processed before end events instead.

- **Time:** `O(n log n)` to sort the `2n` events.
- **Space:** `O(n)` for the event list.

## Choosing an Approach

- If the problem asks you to **merge or inspect intervals from left to right**, sort by start time.
- If the problem asks you to **maximize the number of compatible intervals** or minimize removals, sort by end time.
- If the problem asks **how many intervals are active** at a time, use a sweep line.
