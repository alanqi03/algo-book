# Linked Lists

Linked-list problems are mostly pointer-management problems. Unlike an array, a linked list does not support direct indexing. To reach a node, you must follow the chain from the head, but nodes can be inserted, removed, or rearranged in `O(1)` time once you have the correct pointers.

This chapter covers the reusable patterns behind most linked-list interview problems.

## Data Structure

A singly linked-list node stores a value and a pointer to the next node:

```{code-block} python
---
linenos:
---
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next
```

A list such as `1 -> 2 -> 3 -> None` is represented by a `head` pointer to the node containing `1`.

### Basic Traversal

Use a separate pointer when traversing so that the original `head` is not lost:

```{code-block} python
---
linenos:
---
def to_list(head):
    values = []
    curr = head

    while curr:
        values.append(curr.val)
        curr = curr.next

    return values
```

Traversal takes `O(n)` time and `O(1)` auxiliary space, excluding the returned values.

## Pointer Safety

Before changing `curr.next`, decide whether the rest of the list still needs to be reached. If so, save it first:

```{code-block} python
next_node = curr.next
curr.next = prev
curr = next_node
```

The most common linked-list bugs come from:

1. Losing the remainder of the list after overwriting a `next` pointer.
2. Dereferencing `None`, especially with expressions such as `fast.next.next`.
3. Forgetting that an operation can replace the head.
4. Creating a cycle accidentally while reconnecting nodes.

Always test an empty list, a one-node list, a two-node list, and a case where the head changes.

## Sentinel (Dummy) Nodes

A sentinel node is a temporary node placed before the real head. It makes the head behave like every other node, which removes special cases when inserting or deleting at the front.

This example removes every node with a target value:

```{code-block} python
---
linenos:
---
def remove_elements(head, target):
    dummy = ListNode(0, head)
    prev = dummy
    curr = head

    while curr:
        if curr.val == target:
            prev.next = curr.next
        else:
            prev = curr
        curr = curr.next

    return dummy.next
```

Notice that `prev` advances only when `curr` is kept. Return `dummy.next`, not `dummy`, because the sentinel is not part of the result.

Dummy nodes are especially useful for:

- deleting the head;
- merging lists;
- constructing a new result list;
- keeping stable `head` and `tail` boundaries in a doubly linked list.

## Reverse a Linked List

Reversal is a building block for palindrome, reorder, and sublist problems.

### Iterative Reversal

Maintain `prev` and `curr`. Save the next node before reversing the current edge:

```{code-block} python
---
linenos:
---
def reverse_list(head):
    prev = None
    curr = head

    while curr:
        next_node = curr.next
        curr.next = prev
        prev = curr
        curr = next_node

    return prev
```

The final `prev` is the new head. This takes `O(n)` time and `O(1)` auxiliary space.

### Recursive Reversal

The recursive version reverses the suffix, then attaches the current node to its end:

```{code-block} python
---
linenos:
---
def reverse_list_recursive(head):
    if not head or not head.next:
        return head

    new_head = reverse_list_recursive(head.next)
    head.next.next = head
    head.next = None
    return new_head
```

This also takes `O(n)` time, but it uses `O(n)` call-stack space. Prefer the iterative version when the list may be long.

## Merge Two Sorted Lists

Use a dummy node to build the result and a `tail` pointer to track where the next node belongs:

```{code-block} python
---
linenos:
---
def merge_sorted_lists(a, b):
    dummy = ListNode()
    tail = dummy

    while a and b:
        if a.val <= b.val:
            tail.next = a
            a = a.next
        else:
            tail.next = b
            b = b.next
        tail = tail.next

    tail.next = a if a else b
    return dummy.next
```

Each node is visited once, so the algorithm takes `O(n + m)` time and `O(1)` auxiliary space. It reuses the input nodes rather than creating copies.

## Fast and Slow Pointers

Floyd's tortoise-and-hare pattern uses two pointers moving at different speeds:

- `slow` moves one node at a time;
- `fast` moves two nodes at a time.

Always check both `fast` and `fast.next` before evaluating `fast.next.next`.

### Find the Middle

```{code-block} python
---
linenos:
---
def middle_node(head):
    slow = fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next

    return slow
```

When the list has even length, this version returns the second middle node. It takes `O(n)` time and `O(1)` space.

### Detect a Cycle

If there is no cycle, `fast` eventually reaches `None`. If there is a cycle, the faster pointer eventually catches the slower pointer inside it.

```{code-block} python
---
linenos:
---
def has_cycle(head):
    slow = fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            return True

    return False
```

Use identity (`is`) rather than comparing node values. Different nodes may contain the same value.

### Find the Start of a Cycle

After `slow` and `fast` meet, place one pointer back at `head`. Move both pointers one step at a time; their next meeting point is the cycle entrance.

```{code-block} python
---
linenos:
---
def cycle_start(head):
    slow = fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            break
    else:
        return None

    finder = head
    while finder is not slow:
        finder = finder.next
        slow = slow.next

    return finder
```

Both cycle algorithms take `O(n)` time and `O(1)` space.

## Fixed-Gap Two Pointers

Move one pointer ahead by a fixed number of nodes, then move both pointers together. The gap between them remains constant.

### Remove the Nth Node From the End

Move `fast` `n` nodes ahead of `slow`. When `fast` reaches the last node, `slow.next` is the node to remove.

```{code-block} python
---
linenos:
---
def remove_nth_from_end(head, n):
    dummy = ListNode(0, head)
    slow = fast = dummy

    for _ in range(n):
        fast = fast.next

    while fast.next:
        slow = slow.next
        fast = fast.next

    slow.next = slow.next.next
    return dummy.next
```

The dummy node handles the case where the original head is removed. This solution assumes `1 <= n <= length` and takes `O(n)` time and `O(1)` space.

### Find the Intersection of Two Lists

When a pointer reaches the end of one list, redirect it to the other list's head. Each pointer then travels the same total distance: `length_a + length_b`.

```{code-block} python
---
linenos:
---
def intersection_node(head_a, head_b):
    a, b = head_a, head_b

    while a is not b:
        a = a.next if a else head_b
        b = b.next if b else head_a

    return a
```

The pointers meet at the shared node or at `None`. The algorithm takes `O(n + m)` time and `O(1)` space.

## Reorder a List

To transform `L0 -> L1 -> ... -> Ln` into `L0 -> Ln -> L1 -> Ln-1 -> ...`:

1. Find the end of the first half.
2. Reverse the second half.
3. Weave the two halves together.

```{code-block} python
---
linenos:
---
def reorder_list(head):
    if not head or not head.next:
        return

    # 1. Find the final node of the first half.
    slow = fast = head
    while fast.next and fast.next.next:
        slow = slow.next
        fast = fast.next.next

    # 2. Detach and reverse the second half.
    second = reverse_list(slow.next)
    slow.next = None

    # 3. Alternate nodes from the two halves.
    first = head
    while second:
        first_next = first.next
        second_next = second.next

        first.next = second
        second.next = first_next

        first = first_next
        second = second_next
```

The split is important: `slow.next = None` prevents an accidental cycle. The algorithm takes `O(n)` time and `O(1)` space.

## Check Whether a List Is a Palindrome

Find the first half's end, reverse the second half, and compare corresponding values. Restoring the second half afterward avoids surprising the caller by mutating the input permanently.

```{code-block} python
---
linenos:
---
def is_palindrome(head):
    if not head or not head.next:
        return True

    first_half_end = head
    fast = head
    while fast.next and fast.next.next:
        first_half_end = first_half_end.next
        fast = fast.next.next

    second_half = reverse_list(first_half_end.next)

    left, right = head, second_half
    result = True
    while right:
        if left.val != right.val:
            result = False
            break
        left = left.next
        right = right.next

    first_half_end.next = reverse_list(second_half)
    return result
```

This takes `O(n)` time and `O(1)` auxiliary space.

## Add Numbers Digit by Digit

When digits are stored in reverse order, process both lists from left to right while carrying overflow into the next place.

```{code-block} python
---
linenos:
---
def add_two_numbers(a, b):
    dummy = ListNode()
    tail = dummy
    carry = 0

    while a or b or carry:
        a_val = a.val if a else 0
        b_val = b.val if b else 0
        carry, digit = divmod(a_val + b_val + carry, 10)

        tail.next = ListNode(digit)
        tail = tail.next

        a = a.next if a else None
        b = b.next if b else None

    return dummy.next
```

The loop continues while `carry` is nonzero so that a final digit is not lost. The algorithm takes `O(max(n, m))` time and uses `O(max(n, m))` space for the result.

## Copy a List With Random Pointers

Suppose every node has both `next` and `random`, where `random` may point anywhere in the list:

```{code-block} python
class RandomNode:
    def __init__(self, val=0, next=None, random=None):
        self.val = val
        self.next = next
        self.random = random
```

A hash map can copy this structure in `O(n)` time and `O(n)` extra space:

```{code-block} python
---
linenos:
---
def copy_random_list(head):
    if not head:
        return None

    copies = {None: None}

    curr = head
    while curr:
        copies[curr] = RandomNode(curr.val)
        curr = curr.next

    curr = head
    while curr:
        copies[curr].next = copies[curr.next]
        copies[curr].random = copies[curr.random]
        curr = curr.next

    return copies[head]
```

The key idea is to map each original node object—not its value—to its corresponding copied node.

## LRU Cache: Hash Map + Doubly Linked List

An LRU (least recently used) cache combines two data structures:

- a hash map finds a cached key in `O(1)` time;
- a doubly linked list maintains usage order in `O(1)` time.

The most recently used item is kept near `right`; the least recently used item is kept near `left`. Both boundary nodes are sentinels.

```{code-block} python
---
linenos:
---
class DoublyNode:
    def __init__(self, key=0, value=0):
        self.key = key
        self.value = value
        self.prev = None
        self.next = None


class LRUCache:
    def __init__(self, capacity):
        self.capacity = capacity
        self.nodes = {}

        self.left = DoublyNode()   # LRU sentinel
        self.right = DoublyNode()  # MRU sentinel
        self.left.next = self.right
        self.right.prev = self.left

    def _remove(self, node):
        node.prev.next = node.next
        node.next.prev = node.prev

    def _insert_mru(self, node):
        previous_mru = self.right.prev
        previous_mru.next = node
        node.prev = previous_mru
        node.next = self.right
        self.right.prev = node

    def get(self, key):
        if key not in self.nodes:
            return -1

        node = self.nodes[key]
        self._remove(node)
        self._insert_mru(node)
        return node.value

    def put(self, key, value):
        if key in self.nodes:
            self._remove(self.nodes[key])

        node = DoublyNode(key, value)
        self.nodes[key] = node
        self._insert_mru(node)

        if len(self.nodes) > self.capacity:
            lru = self.left.next
            self._remove(lru)
            del self.nodes[lru.key]
```

Both `get` and `put` take `O(1)` average time, while the cache uses `O(capacity)` space.

## Pattern Summary

| Pattern | Typical use | Time | Auxiliary space |
| --- | --- | ---: | ---: |
| Dummy node | Insert or delete near the head | `O(n)` traversal | `O(1)` |
| Iterative reversal | Reverse a list or one of its halves | `O(n)` | `O(1)` |
| Fast and slow pointers | Middle, cycle detection, cycle entrance | `O(n)` | `O(1)` |
| Fixed pointer gap | Nth node from the end | `O(n)` | `O(1)` |
| Pointer switching | Intersection of two lists | `O(n + m)` | `O(1)` |
| Split, reverse, merge | Reorder and palindrome problems | `O(n)` | `O(1)` |
| Hash map + linked list | Random pointers and LRU caches | `O(n)` or `O(1)` per operation | `O(n)` |

## General Tips

1. Draw the nodes and arrows before writing code. Label every pointer that will move.
2. Save `next` before changing an edge unless the old edge is no longer needed.
3. Use `is` when checking whether two variables refer to the same node.
4. Use a dummy node whenever the head might be inserted, deleted, or replaced.
5. Decide whether mutating the input is allowed. If not, create new nodes or restore changed links.
6. Recursive solutions are often elegant, but they use call-stack space and can exceed Python's recursion limit.
